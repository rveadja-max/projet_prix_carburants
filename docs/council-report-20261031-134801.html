LLM Council — Revue globale du projet

Aide au plein de la flotte (Livraisons Exemple) · Projet de formation data mining

SEP Conseil : Liam Arnault · Samuel Sidoli · Hervé Adjakossa · Antoine Pholulamdeth

Question soumise au conseil : la logique métier et les fonctionnalités sont-elles défendables, et le rendu est-il de qualité et raisonnablement calibré sur les données ?

Verdict du Chairman

Le rendu est défendable dans sa démarche — pas encore dans ses chiffres ni dans son récit.

La démarche (cartes, journal IA, plafond affiché, 3 écrans, séparation backend/frontend) n'est contestée par aucun conseiller. Deux risques sont en revanche éliminatoires pour la note et doivent être traités avant toute autre chose :

  • Refaire l'évaluation honnêtement : choisir le modèle sur la validation (ce qui livrera « sans Brent », le seul déployable), intervalles de confiance clusterisés par semaine (vrai N ≈ 24, pas 55 262), annualisation sur la borne basse (~87 €/an, pas 420), analyse de sensibilité du seuil 0,26, coût logistique de l'attente (~0,7 €/plein vs détour), justification de la purge de 3 j.
  • Retourner le récit : faire de « quel levier vaut combien ? » la colonne vertébrale de la soutenance, avec la conclusion honnête en titre — le timing vaut ~0,2 % du budget, la station ~6× plus, et le modèle supervisé (exigé par la grille) sert à le prouver chiffré.

Consensus Où le conseil s'accorde

  • La matérialité économique du levier « timing » est faible et le récit ne l'assume pas.
  • Le levier « station » domine le levier « timing » d'un facteur ~6.
  • Le gain de 420 €/an est fragile statistiquement (concentré sur mai-juin, juillet négatif).

Désaccord Où le conseil s'affronte

  • Faut-il un modèle ? B dit « non, pas pour le timing » ; D tranche : l'honnêteté devient le titre, le modèle reste (exigé par la grille) mais repositionné en quantificateur d'un levier borné.
  • Fusionner « où » + « quand » (≈3 100 €/an) ? Rejeté à l'unanimité des relecteurs : deux estimations corrélées ne s'additionnent pas.
  • Quel modèle livrer ? A démontre que seul « sans Brent » est déployable ; non réfuté.

Angles morts Ce que la relecture a révélé

  • Le coût logistique d'« attendre 3 jours » n'a jamais été calculé — le gain peut être négatif en coût complet.
  • Les prix ne sont pas déclarés quotidiennement : le « prix à J+3 » est souvent reporté → cible plate.
  • Personne n'a relu seuil_optimal ni la Data Quality Card avant de débattre des chiffres.
  • La grille N3 sanctionne surtout la fuite de données et le choix sur le test.

La seule chose à faire d'abord

Exécuter, chronomètre en main, le test du clone vide sur une machine avec réseau : git clone → pip install -r requirements.txt → python -m backend.train → python -m pytest → streamlit run frontend/app.py. C'est le critère qui coûte le plus de points, il n'a jamais été validé de bout en bout, et il produit le metriques.json frais dont dépendent tous les chiffres corrigés ensuite.

Réponses complètes des conseillers

The Contrarian
Quel modèle est livrable ? Brent veille gagne (0,66) mais le Brent gratuit a 8 j de retard et Brent 8 j (0,93) fait pire que sans Brent (0,90) → seul « sans Brent » est déployable. Choisir « Brent veille » sur le regret test = choix de modèle sur le test, ce que la grille pénalise le plus. 420 €/an gonflés (gain concentré mai-juin, juillet négatif ; borne basse d'IC ≈ 87 €/an). IC trop étroit : 55 262 lignes corrélées, vrai N ≈ 24 semaines → refaire clusterisé par semaine. Purge de 3 j suffisante avec des fenêtres 7-30 j ? Saut du 1er janv 2026 = aveu d'échec sur un critère noté. Seuil 0,26 sans analyse de sensibilité. 420 € = 0,2 % du budget (~212 k€), 20 c€/plein : défendre la matérialité ou assumer la démo pédagogique.
The First Principles Thinker
La vraie question n'est pas « prédire une hausse à J+3 » : la flotte ne gagne que si la variance du prix sur 3 j dépasse le coût de la décision ; on capture 27 % d'un gâteau = 0,2 % du budget. Fallait-il un modèle ? Réponse possible : « non, pas pour le timing — voici la preuve chiffrée ». (1) La cible « hausse stricte » jette l'économie (+0,1 et +5 c€ pareils) ; la décision dépend de l'espérance — prédire le delta ? (2) Le seuil 0,26 suppose une asymétrie de coûts absente des prix. (3) Le levier est ailleurs : le choix de station (>5 c€/L) domine le timing (0,9). Reformulation : « quel levier — station, jour, ou les deux — vaut combien ? »
The Expansionist
Le « où » pèse 6× le « quand » (2 710 € vs 420 €) → fusionner en « ici + aujourd'hui » ≈3 100 €/an = chiffre de titre. Rendre la valeur visible : compteur d'économies, export PDF hebdo, job quotidien → du produit. Démo vivante le jour J. Bonus : détection d'anomalies (écran « Opportunités »). Simulateur what-if (Brent +5 $). Réplicabilité (une ligne de config → essence/autre département). Benchmark externe vs baromètre national. Tout réutilise l'existant : monétiser, automatiser, généraliser.
The Outsider
Clair : la question « aujourd'hui ou +3 jours » est compréhensible ; les 3 onglets répondent au brief ; cartes + journal IA inspirent confiance ; plafond et volumes fictifs = honnêteté. Flou : « regret 1,24 c€/L » non défini ; on ne sait pas si 0,90 est spectaculaire ou marginal sans ancre (prix du litre ? règle naïve ?). Inquiète : 420 €/an sur volumes fictifs dérisoire (10 €/an/véhicule) ; gain de 2 mois de crise sur une seule période (chance ?) ; Brent « payant » pour 0,24 c€/L incohérent. Verdict : démarche sérieuse mais cas métier faible non assumé — mettre l'honnêteté en titre, pas en note de bas de page.
The Executor
Livrable, mais « tourne du premier coup depuis un clone vide » n'a jamais été validé de bout en bout avec réseau = LE blocage. (1) Test du clone vide avec réseau chronométré (clone → pip → train → pytest → streamlit). (2) Marquer les 14 tests réseau (skip si données absentes) pour un pytest hors-ligne vert. (3) Conflit chiffres README / drift : figer la date + documenter, ou relancer le train la veille et recopier metriques.json. (4) Avant remise : versions pinnées Ubuntu 24.04, aucun chemin absolu, AppTest sans réseau, PDF régénérés, git propre. Risque : data.gouv.fr en panne le jour J → copie locale des brutes + manifeste.
Relecture croisée (faits saillants)
  • A jugée la plus forte par 4 relecteurs sur 5 : seule à attaquer la validité statistique (choix sur le test, pseudo-réplication, annualisation) — fautes notées, falsifiables, corrigeables.
  • B jugée la plus forte par 1 relecteur : recadrage décisionnel (espérance du delta, levier « station » dominant).
  • C jugée le plus grand angle mort par les 5 relecteurs : fonctionnalités empilées sur un socle non validé ; addition d'estimations corrélées.
  • Angle mort de B : ignore que la grille impose une méthode supervisée.
  • Manques soulevés en relecture : coût logistique de l'attente ; prix non déclarés quotidiennement ; reproductibilité des chiffres (metriques.json, seed, manifeste) ; la grille N3 sanctionne surtout fuite et choix sur test.
